# LearnLang — build report & session memory

Completed: 2026-09-25. Written by the agent as a durable record of how this project was built, what was decided, and what to check before extending it.

## What this is
Expo (SDK 57) / React Native app, TypeScript + expo-router, targeting Android and iOS from `C:\Codes\qoder\LearnLang`. Leitner flashcard app containing the 1000 most frequent words for 6 languages: English (en), Persian (fa), Armenian (hy), Russian (ru), German (de), Swedish (sv) — 6000 entries total.

## Requirements as implemented (interpretation notes!)
- 7 Leitner boxes fixed to user-requested intervals: 1min, 3min, 10min, 1hour, 1day, 1week, 1month (30d) — `BOXES` in `src/lib/leitner.ts`.
- "User can select to repeat the word after X" → after revealing a card, the user taps any of the 7 interval chips to schedule the card's next review directly. Two shortcut buttons: **Again** (reset to box 0 = 1 min) and **Got it** (promote to next box, Leitner-style).
- "Each word shown again after the specified duration" → cards due are queued first (`buildSession`); if a scheduled card comes due *during* a session (e.g. 1m/3m chips) it re-enters the queue automatically with a live countdown; `REQUEUE_WINDOW_MS` = 20 min in `src/app/study.tsx` (waits longer than that end the session instead).
- Sessions take all due cards + up to 20 unseen ("new") words in frequency order (`NEW_PER_SESSION`).
- Persistence: one AsyncStorage key per language, `learnlang:deck:<id>`, storing `Record<wordIndex, {box, due}>`. Saved after every answer. Long-press a language on Home = reset that deck.

## File map (non-boilerplate)
- `src/lib/leitner.ts` — pure scheduling model (types, BOXES, buildSession, dueIndices, nextReviewAt, formatRemaining)
- `src/lib/storage.ts` — AsyncStorage load/save/reset
- `src/data/languages.ts` — language metadata (RTL flag for Persian) + static JSON imports
- `src/data/words/{en,fa,hy,ru,de,sv}.json` — 1000 entries each: `{word, meaning, roman}`; `meaning` = English gloss (for en: short English definition), `roman` = transliteration (fa/hy/ru only, else `""`)
- `src/app/index.tsx` — Home: per-language due/learned/mastered + progress bars
- `src/app/study.tsx` — study session: flip card, grade chips, waiting countdown, done view
- Template demo screens/components (explore, app-tabs, themed-*, use-theme, use-color-scheme*, global.css) were DELETED; screens use RN `useColorScheme` + `Colors` from `src/constants/theme.ts` directly.

## Key decisions & gotchas
- Chose Expo over bare RN CLI (user-approved). Native `android/`/`ios/` dirs intentionally absent — generated via CNG (`expo prebuild` / `expo run:*` / EAS). Never hand-create them (see AGENTS.md).
- Study screen is deliberately event-driven: phase transitions happen in `applyQueue()` called from handlers/intervals, NOT in effects — this was required to pass `react-hooks/set-state-in-effect` and react-hooks purity lint rules (strict + React Compiler enabled). Keep it that way: no `Date.now()` or setState during render.
- `npx expo lint` bootstraps ESLint on first run and errors the first time; just rerun.
- JSON imports typecheck via `resolveJsonModule` inherited from `expo/tsconfig.base`.

## Data provenance caveat
Word lists were AI-generated by six subagents, not taken from a certified frequency corpus. Counts verified programmatically (1000/1000 unique per file, strict JSON). Ordering is approximate beyond roughly the first few hundred entries; Persian romanization is simplified (not DIN/ILSI); some homographs collapsed. If the user wants corpus-grade lists, replace `src/data/words/*.json` keeping the same schema — no code changes needed.

- `npx tsc --noEmit` → clean
- `npx expo lint` → 0 errors, 0 warnings
- `npx expo export --platform android --platform ios` → Hermes bundles produced (~2.6–2.9 MB)
- `npx expo export --platform web` → static render of `/` and `/study` OK (home showed all languages)
- Scheduling logic unit-smoke-tested in Node: no card re-enters before due time; 1m card returned after 2 min; empty deck → 20 new cards in order.
- NOT tested: real device/simulator UI (no emulator in the build environment).

## Run / build
- `npm run android` / `npm run ios` (emulator/simulator/device via Expo Go — AsyncStorage is supported in Expo Go)
- Store binaries: `npx eas build`
